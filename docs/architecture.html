Data flow: a filter change

  1. The user picks a filter in FilterBar.vueThere are 4 filters: Time Period, Warehouse, Category and Order Status.
  2. useFilters() updates its shared refsThe refs live at module scope, so every view reads the same filter state. getCurrentFilters() maps the period to month.
  3. The view watches the filters and calls api.jsValues set to "all" are dropped. The rest become query params, e.g. /api/orders?warehouse=...&month=Q3-2025.
  4. FastAPI filters the in-memory listsapply_filters matches warehouse, category and status. filter_by_month matches a month or quarter against order_date.
  5. Pydantic validates the response, which comes back as JSONThe response models are InventoryItem, Order, DemandForecast and BacklogItem.
  6. The view stores the raw data in refs and derives the rest with computedTotals and charts are computed from the raw data. useI18n handles en/ja translations, and formatCurrency converts USD to JPY at a fixed rate of 150.

Things to know

Missing endpoints. api.js defines getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder and getPurchaseOrderByBacklogItem, but main.py has no /tasks or /purchase-orders routes. Those calls return 404.
Inconsistent API access. Reports.vue calls axios directly with a hard-coded URL instead of going through api.js. The base URL localhost:8001 is hard-coded in both places.
Hard-coded quarters. QUARTER_MAP only covers 2025. A quarter outside it, such as Q1-2026, returns unfiltered data.
Mock auth. useAuth returns a hard-coded user and task list. There is no real login.
